今天是一个值得标记的知识管理里程碑。借鉴 Andrej Karpathy 公开的 LLM Wiki 三层架构理论——也就是他所谓的「Zettelkasten + LLM」模式，我终于对个人数据库动了次真格的大手术。

Karpathy 这套框架的逻辑非常清晰：Source 原始资料层 → Wiki 知识编译层 → Schema 规范指导层。信息进来先沉淀，再消化，最后形成可检索、可更新的结构化知识。不是把东西存起来就完事了，而是让 LLM 成为知识的主动管理者。

具体做的工作有三件。第一，把工厂和个人的两套 Obsidian 资料库彻底分开，各自独立运营，分别基于三层结构搭建底层架构。两套知识域的逻辑差异足够大，混在一起只会互相干扰。第二，架构搭建的工具链上，先用 Claude Code 完成了主体框架（额度很快就用尽了），然后切换到国产的 GLM-5 继续推进——不得不说，国产模型在这个场景已经能打了。第三，统一调整了所有目录路径，确保体系一致性，不留烂尾。

核心目标就一个：打造真正可用的个人第二大脑。把散落在各处的知识碎片系统化地萃取出来，形成一个可以持续更新、高效检索的知识网络。在这个 AI 时代，每个人最珍贵的不是面上的公开知识，而是自己独特的见解、与个人三观建立的独特视角。善于记录自己的心得和感想，才是真正值得做的事。

不过构建只是起点。后续真正的挑战在于维护机制——怎么持续把有价值的信息经分析后作为原始资料喂给知识库，让雪球滚起来。还有一个更让我兴奋的方向：个人画像。我已经开始着手让系统积累关于我个人三观、性格、爱好的数据，目前还很初阶，但远期目标是让这些数据生成符合我个人性格的判断和辅助。从「存资料」进化到「编译知识」，这条路才刚刚开始。

## 关键操作
- 基于 Karpathy LLM Wiki 三层理论重构个人知识库架构
- 将工厂与个人两套 Obsidian 资料库独立分离，各自搭建三层结构
- 使用 Claude Code + GLM-5 接力完成架构搭建
- 统一更新所有目录路径

## 碎片想法
- Karpathy 的三层架构核心是「先编译再查询」，不是存了就能用
- 工厂和个人的知识域必须分开，逻辑差异太大
- 国产模型在知识库搭建这种场景已经能顶上来了
- 个人画像是给第二大脑装一个「性格引擎」，让 AI 的输出更懂你
